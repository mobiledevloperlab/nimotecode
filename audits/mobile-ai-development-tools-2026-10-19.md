# Mobile development tools comparison: fact audit

Review date: 2026-10-19. Scope: the English and Chinese comparison pages and their shared data. Final 7 × 23 matrix, evidence excerpts, review dates, confidence, implementation, Pro and host flags, and platform restrictions live in [`mobileDevelopmentCompetitors.ts`](../docs/.vitepress/theme/data/mobileDevelopmentCompetitors.ts). The page renders this same matrix on both routes. “Not verified” records a lack of sufficient first-party evidence; it is not a negative finding.

## Original implementation and root cause

The old English and Chinese Markdown pages supplied introductions and mounted `MobileDevToolComparison.vue`. The component read `mobileDevelopmentCompetitors.ts`, which contained 20 broad rows, loosely typed `yes/partial/no/unknown` cells, product-level source lists, and review dates. `config.ts` derived the ItemList schema from the same product list. Canonical, alternate-language, Open Graph and breadcrumb tags are generated by the existing VitePress config.

Repeated phrases such as “Not confirmed Not confirmed”, “Host-centered Host-centered” and “Pro workflow Pro workflow” came from the component's accessible status label plus a visible note when both conveyed the same judgment; product-level info text also duplicated qualifiers already shown in adjacent rows. The component now renders one localized status label and a distinct implementation/limitation note. This was data/component composition, not duplicate SSR/client hydration and not a CSS issue.

## Candidate products and remaining uncertainty

[Port22](https://www.tryport22.com/) is relevant as a Mac+iPhone companion for existing CLI-agent sessions; its official site documents Mac agent pairing and free/paid session caps. [AgentsRoom](https://agentsroom.dev/) is relevant as a desktop agent environment with iOS/Android companions; its [remote-control page](https://agentsroom.dev/features/remote-agent-control) documents mobile steering and host dependence. Neither was added as an eighth/ninth table column because their complete feature-by-feature evidence and platform/access matrix has not been recorded.

Across all seven products, every unverified matrix cell is an explicit open research item. In particular, mobile-native LSP/debug/conflict UI and ACP/MCP support for most competitors; Redock web preview; Termius/Blink host-process persistence; and application-wide licenses except Blink and Orca remain unverified. NimoteCode's application implementation source is absent from this website repository, so release-note/documentation cross-check is complete but source-level confirmation is not.

## Validation and maintenance

Run `npm run docs:build`, `npm run docs:check`, and `npm run compare:check`. The latter checks all 161 cells, official evidence for affirmative/negative assertions, review dates, locale parity by shared model, duplicate status notes and SSR output. `npm run compare:check -- --links` additionally checks evidence URLs with HTTP requests. An HTTP failure or timeout must be investigated; it must not silently advance the verification date. The matrix's date is tied to its evidence records, so updating a date requires rechecking those pages.

Final run: build passed; site checks passed (186 routes); matrix checks passed (7 products, 23 features); all 34 distinct evidence URLs returned a successful HTTP response; isolated TypeScript check of the matrix passed; `git diff --check` passed. There is no configured repository-wide typecheck, lint or unit-test script. No browser executable was available for phone/tablet/desktop visual testing. The final source of truth is the shared matrix; both localized pages and the home preview read from it.
