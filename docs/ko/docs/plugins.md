# 사용자 지정 플러그인

사용자 지정 플러그인은 작업 공간 데이터, 양식 및 동작을 재사용 가능한 패널로 구성합니다. Git, LSP, Tasks, Terminal, Agent 정보를 모아 표시하거나 자주 사용하는 기본 패널의 바로가기를 만들 수 있습니다.

## 첫 플러그인 만들기

[AI 설정](/ko/docs/configuration)에서 모델을 구성한 뒤 플러그인이 사용할 작업 공간을 엽니다.

1. **AI custom plugins**를 열고 **Create plugin**을 선택합니다.
2. 필요한 정보와 동작을 설명합니다. 예: “현재 브랜치, 변경된 파일, LSP 오류 수를 표시하고 소스 제어 바로가기를 추가해 줘.”
3. 같은 대화에서 결과를 수정합니다. 변경할 필드, 레이블 및 동작을 구체적으로 설명하세요.
4. 패널을 미리 보고 요구 사항에 맞으면 저장하고 설치합니다. 설치를 승인하기 전에 요청 권한을 확인하세요.

## 데이터 및 동작 선택

| 요구 사항 | 플러그인 기능 |
| --- | --- |
| 현재 프로젝트 확인 | 작업 공간, Git, LSP, Tasks, 터미널 또는 Agent 데이터를 표시합니다. |
| 도구 열기 | 기본 Git, Tasks, Terminal, AI 및 편집기 패널의 바로가기를 제공합니다. |
| 입력 수집 | 양식 필드를 추가하고 지원되는 동작에서 값을 사용합니다. |
| 워크플로 실행 | 읽기와 동작을 조합하고 단계 간 결과를 전달하며 조건 또는 재시도를 정의합니다. |
| 스크립트 실행 | 선택한 SSH 또는 Local Linux 환경에서 Python, JavaScript 또는 Shell을 실행합니다. |

데이터는 현재 작업 공간을 따릅니다. 작업 공간을 바꾸면 플러그인의 컨텍스트도 바뀝니다. 파일 바로가기에는 안정적인 네이티브 경로가 필요하므로 문서 제공자 작업 공간에서는 사용할 수 없습니다.

## 미리보기, 권한 및 실행

미리보기에서는 파일 변경, 요청 전송 또는 명령 실행 없이 패널을 확인합니다. 설치나 업데이트 전에 요청 권한을 검토하세요. 파일 쓰기, 네트워크 요청, 터미널 명령, 작업 실행 및 파일 열기는 호출 시 확인이 필요합니다.

스크립트는 대상 환경에 이미 설치된 인터프리터를 사용하며 해당 계정 권한으로 실행됩니다. 필요한 Python, Node.js 또는 셸 환경을 먼저 준비하세요. 플러그인은 언어 서버나 디버그 어댑터를 설치하지 않습니다. [LSP](/ko/docs/lsp) 및 [디버깅](/ko/docs/debug)에서 설정하세요.

## 플러그인 편집 및 관리

플러그인 대화를 이어 가며 기존 패널을 수정합니다. 저장 전에 변경 내용을 미리 보고 업데이트 시 권한 변경을 확인합니다. 플러그인 정의와 양식 구성은 별도로 저장됩니다. 활성화, 비활성화 또는 최근 버전 복원이 가능합니다.

기본 패널 표시 및 편집기 글꼴 설정은 [설정](/ko/docs/settings#panel-and-editor-preferences)을 참고하세요.

## 백그라운드 작업 및 일정

Android 클라이언트는 SSH 또는 Local Linux 대상에서 백그라운드 워크플로와 예약 실행을 지원합니다. 대상에는 Python 3.9 이상과 SQLite가 필요합니다. iOS는 포그라운드 플러그인 동작을 지원하지만 백그라운드 워크플로나 예약 실행은 제공하지 않습니다.

플러그인 대화에서 워크플로와 일정을 설명합니다. 배포 전에 실행 계획, 입력 및 일정을 확인하세요. **Background jobs & schedules**에서 출력을 확인하고 새로 고침, 일시 중지, 재개 또는 취소할 수 있습니다. 대상 환경이 실행 중이면 앱 연결이 끊겨도 작업이 계속될 수 있습니다. 대상이 재부팅되면 복구를 위해 다시 연결해야 할 수 있습니다.

패널 이동, LSP 동작 및 기본 구성 작업은 포그라운드에서 실행됩니다. 백그라운드 실행에는 양식의 비밀 필드가 보관되지 않으므로 무인 실행에는 대상 환경의 인증 정보를 사용하세요.
