NimoteCode 演示展示了这款产品面向的工作流：不切换工具，就从一次远程 SSH 连接走向项目检查、代码编辑、终端验证、Git 审查与 AI 辅助。

## 演示展示了什么

### 1. 打开一个移动开发工作区

NimoteCode 从项目出发，而不是一个独立的命令提示符。设备上的项目用本地 Explorer，或通过 [SSH 工作区](/zh/docs/ssh) 连接远程主机。Explorer 与编辑器让任务背后的文件始终可见、可触达。

### 2. 检查并编辑代码

打开受影响的文件，通过编辑器标签页跟随相邻代码，做一处聚焦改动。重点不是用手机写一个大型功能，而是在没有电脑时，也能完成那些紧急或范围明确的工作。

### 3. 在上下文中运行终端命令

用终端检查日志、运行测试、查看服务状态或验证改动。因为终端位于同一个工作区，代码与输出始终相连。操作细节见[终端](/zh/docs/terminal)。

### 4. 发布前审查 Git

工作流以一处可审查的改动收尾。[源代码管理](/zh/docs/source-control)把 diff、暂存、提交与分支上下文放在你编辑的文件旁。这是把一次快速 shell 修复，与受控的开发闭环区分开来的地方。

### 5. 让 AI 帮你做下一个决定

AI Chat 能帮助解释代码或报错。AI Agent 可以协助受控的多步骤任务。两种情况都以真实工作区为准，应用它们提出的命令或改动前应先审查。

## 这套工作流适合谁

演示特别适合需要在手机或平板上检查、修复或审查真实项目的开发者、运维工程师与值班响应者。工作流背后的场景见 [移动 IDE](/zh/mobile-ide)、[SSH IDE](/zh/ssh-ide) 与[移动 AI 编程](/zh/mobile-ai-coding)。
